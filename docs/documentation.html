Documentation

Everything you need to install, configure, and use CLI Snitch to monitor and control network connections on macOS.

Installation

Homebrew (recommended)

brew tap nickciolpan/tap
brew install cli-snitch

GitHub Releases

Download the latest binary for your architecture from GitHub Releases, then:

tar -xzf cli-snitch-v2.0.0-darwin-arm64.tar.gz
sudo mv cli-snitch /usr/local/bin/
chmod +x /usr/local/bin/cli-snitch

Build from source

git clone https://github.com/nickciolpan/cli-snitch
cd cli-snitch
make build
# Binary is at ./cli-snitch

Prerequisites

  • macOS (tested on Sonoma and later)
  • Root privileges — required for watch, firewall, and daemon commands
  • Go 1.19+ — only if building from source

Quick Start

Start monitoring in three commands:

# 1. Install
brew install nickciolpan/tap/cli-snitch

# 2. Start monitoring (requires sudo)
sudo cli-snitch watch

# 3. That's it. You'll see prompts for every new connection.
Tip: CLI Snitch monitors both TCP and UDP connections. The first scan may show many connections — after you make decisions, subsequent scans will be quiet since rules are applied automatically.

Monitoring Connections

The watch command starts real-time monitoring. It scans active connections every 2 seconds using lsof.

sudo cli-snitch watch

When a new outbound connection is detected that doesn't match any rule, you'll see a detailed prompt:

🚨 New Outbound Connection Detected
────────────────────────────────────────
  Application: Google Chrome
  Destination:  telemetry.example.com:443
  Protocol:     TCP
  Host Info:    Amazon Web Services (AWS)

? What would you like to do with this connection?
> Allow Once
  Allow Always
  Deny Once
  Deny Always

Connections that match existing rules are handled automatically:

✅ claude ALLOWED -> 160.79.104.10:443 [Allow all claude connections]
❌ Google DENIED -> 142.251.31.188:443 [Block Google Chrome]
✅ Mail ALLOWED -> 17.57.144.50:993 [Allow Mail]

Press Ctrl+C to stop. CLI Snitch performs cleanup, saves rules, and displays session statistics.

Making Decisions

Each prompt offers four choices:

ChoiceWhat it does
Allow OncePermit this connection. No rule saved. Won't apply to future connections.
Allow AlwaysPermit and create a persistent rule. You choose the scope next.
Deny OnceBlock this connection. Creates a temporary pfctl rule (expires in 24h).
Deny AlwaysBlock and create a persistent pfctl rule + saved rule. You choose the scope next.

Rule Scopes

For persistent decisions (Allow/Deny Always), you choose how broad the rule should be:

ScopeMatchesExample
ExactProcess + host + portChrome to ads.tracker.com:443 only
Process + HostProcess + host, any portChrome to ads.tracker.com on any port
Process + PortProcess + port, any hostChrome to any host on port 443
Process OnlyAll connections from processBlock everything from Chrome

Managing Rules

List rules

cli-snitch list-rules

📋 Found 3 rules:

allow claude Allow all claude connections
    Scope: process | ID: allow-claude
    Created: 2026-03-24 10:00:00 | Used: 42 times

deny Google Block Google Chrome
    Scope: process | ID: deny-google
    Created: 2026-03-24 10:00:00 | Used: 17 times

Edit a rule

Change any field of an existing rule by its ID:

# Change a deny to allow
cli-snitch edit-rule deny-google --action allow

# Update description and add a host pattern
cli-snitch edit-rule my-rule --description "Updated rule" --pattern "*.example.com"

# Available flags: --action, --description, --host, --port, --pattern

Clear all rules

cli-snitch clear-rules
⚠️ This will delete all 3 rules. Are you sure? (y/N): y
✅ All rules cleared.

Wildcard Patterns

Rules support glob patterns for flexible host matching. The pattern field uses Go's filepath.Match syntax:

PatternMatches
*.google.comwww.google.com, apis.google.com, etc.
*.cdn.*assets.cdn.example, img.cdn.net, etc.
10.0.*.*Any IP in the 10.0.x.x range

Add a pattern when editing a rule:

cli-snitch edit-rule my-rule --pattern "*.analytics.com"

Or include it in an imported JSON rule file (see Import & Export).

Firewall Integration

When you deny a connection, CLI Snitch creates a real pfctl rule in the macOS packet filter. This blocks the connection at the kernel level — not just in the CLI.

Root required. Firewall operations need sudo. Without root, CLI Snitch runs in monitoring-only mode.

Rules are isolated in a pfctl anchor (cli-snitch) so they never conflict with your system firewall rules. Example generated rules:

block out proto tcp from any to malicious.com port 443
block out proto tcp from any to ads.tracker.com
block out proto tcp from any to any port 80

All host and port values are validated with regex before being passed to pfctl, preventing command injection.

Firewall Commands

# Check pfctl integration status
sudo cli-snitch firewall-status

# List active blocking rules in pfctl
sudo cli-snitch list-firewall

# Remove expired temporary rules (from "Deny Once")
sudo cli-snitch firewall-cleanup

# Remove ALL CLI Snitch rules from pfctl
sudo cli-snitch clear-firewall

# Live firewall status feed (Ctrl+C to stop)
sudo cli-snitch firewall-monitor

Connection History

Every allow/deny decision is logged to ~/.cli-snitch/history.jsonl. View it with:

# Last 50 entries (default)
cli-snitch history

# Last 10 entries
cli-snitch history -n 10

# Only denied connections
cli-snitch history --action denied

# Only connections from a specific process
cli-snitch history --process Google

# Combine filters
cli-snitch history --process Google --action denied -n 100

Example output:

📜 Connection History (17 entries):

2026-03-24 12:53:56 ❌ Google denied -> 140.82.114.26:443
2026-03-24 12:53:56 ❌ Google denied -> 54.73.83.130:443

2026-03-24 12:53:57 ✅ claude allowed -> 34.149.66.137:443
2026-03-24 12:53:57 ✅ Cursor allowed -> 104.18.18.125:443

Import & Export Rules

Export

Back up your rules to a JSON file:

cli-snitch export-rules my-rules.json

Import

Load rules from a JSON file. By default this replaces all existing rules:

# Replace all rules
cli-snitch import-rules my-rules.json

# Merge with existing rules
cli-snitch import-rules my-rules.json --merge

Rule JSON format

[
  {
    "id": "block-tracking",
    "process_name": "Google",
    "host": "analytics.google.com",
    "port": "443",
    "pattern": "*.analytics.*",
    "action": "deny",
    "scope": "process_host",
    "description": "Block Google analytics"
  }
]
Scope values: process, process_host, process_port, exact
Action values: allow, deny, allow_once, deny_once

Daemon Mode

Run CLI Snitch as a background service via macOS launchd:

# Install the launchd plist
sudo cli-snitch daemon install

# Start the daemon
sudo cli-snitch daemon start

# Check if it's running
sudo cli-snitch daemon status

# Stop
sudo cli-snitch daemon stop

# Remove completely
sudo cli-snitch daemon uninstall

When running as a daemon, logs go to ~/.cli-snitch/daemon.log. Since there's no terminal for interactive prompts, unknown connections default to "Allow Once".

Process Names

CLI Snitch uses process names from lsof, which truncates them to ~9 characters and may include escaped characters. Some common examples:

Applsof nameNotes
Google ChromeGoogleTruncated from "Google Chrome Helper"
SlackSlack\x20Trailing escaped space
FigmaFigma\x20Trailing escaped space
Dockercom.dockeTruncated bundle ID
MailMailExact match
curlcurlExact match
DNS ResolvermDNSRespoTruncated
Tip: Run sudo lsof -i tcp -i udp -n | awk '{print $1}' | sort -u to see the exact process names on your machine. Use these names in your rules.

Troubleshooting

"Error: CLI Snitch requires sudo privileges"

The watch command needs root to run lsof with full visibility and manage pfctl. Run with sudo:

sudo cli-snitch watch

Prompt blocks other connections

The interactive prompt is serialized — only one prompt shows at a time. While waiting for your decision, other new connections queue up. This is by design to prevent stdin collisions. If you find it overwhelming on first run, consider pre-loading rules for known apps via import-rules.

Rules don't seem to match

Check the exact process name with lsof. Matching is case-insensitive but the process name string must match exactly (including escaped characters like \x20).

Firewall rules not applied

Verify pfctl is available and the anchor is loaded:

sudo cli-snitch firewall-status
sudo cli-snitch system-status

Too many connections on first run

Create a JSON file with allow rules for your common apps and import it before starting:

cli-snitch import-rules my-baseline-rules.json
sudo cli-snitch watch
